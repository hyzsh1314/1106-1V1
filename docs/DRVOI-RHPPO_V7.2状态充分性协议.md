# DRVOI-RHPPO V7.2：状态充分性与动作价值可识别性协议

## 1. 启动原因

V7.1 的响应可识别性门禁通过，但 P1Q 开发门禁失败。完整终局同状态动作探针、三种 critic 结构和 192→768 个 MC 训练上下文均未恢复可泛化的动作排序。因此 V7.2 不再继续调整 Q 阈值、网络宽度或训练 epoch，而是先检验 Q 输入是否包含决定动作价值所需的状态。

本阶段只允许开发集状态充分性诊断。确认性 test、响应模型重训、P1Q、O0 和长训练继续锁定。

## 2. 固定表示

V7.2 同时比较四种表示：

| 名称 | 内容 | 用途 |
|---|---|---|
| registered_v7_1 | 基准 belief、基准动作、未来12维相对响应 | V7.1 失败基线 |
| full_observation | 基准 belief、基准动作、未来39维合法观测 | 可部署的扩展响应候选 |
| future_belief | 未来 belief 与未来39维观测 | 判断是否需要预测未来 latent state |
| mechanistic_oracle | 未来 belief、未来观测、未来低层控制器隐状态 | 机械状态充分性的诊断上界 |

`future_belief` 和 `mechanistic_oracle` 只能用于开发诊断，不能直接作为在线可用输入。若只有 oracle 通过，仍不授权 P1Q。

## 3. 数据隔离

- train seeds：53185、54185；
- validation seed：55185；
- formal-test seed：56185，开发门禁冻结前禁止生成；
- 四种表示必须来自完全相同的环境状态、动作分支和终局回报；
- 每个上下文枚举90个动作，仅合法动作进入门禁；
- continuation 固定为 B0 seed85 确定性策略，并使用共同随机数；
- 所有分支必须到达环境真实终止，不允许截断回报或 bootstrap 冒充 MC 真值。

## 4. 开发门禁

每种表示独立训练同一 `joint_dueling_v1` critic，validation 仅用于早停。冻结门槛保持 V7.1 原值：

1. 成对动作排序准确率不低于0.60，且上下文 bootstrap 95% 区间下界高于0.50；
2. 归一化 argmax 遗憾不高于0.10；
3. 遗憾必须低于随机合法动作对照。

决策顺序：

1. 若 mechanistic oracle 失败，说明当前动作定义或终局价值目标本身不可稳定学习，停止 DRVOI 路线；
2. 若 oracle 通过但所有可部署表示失败，只允许设计新的未来状态预测器，不运行 P1Q；
3. 只有至少一个可部署表示通过，才允许冻结该表示并另行预注册响应训练与一次性 formal test。

## 5. 禁止事项

- 不得观察 validation 后降低门槛；
- 不得用训练集拟合或回合级 Spearman 替代同状态动作门禁；
- 不得把 oracle 特征直接接入在线算法；
- 不得在开发失败后生成 formal-test seed；
- 不得用任务胜率抵消动作价值不可识别性。
